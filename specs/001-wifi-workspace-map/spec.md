# Feature Specification: Wi-Fi 付き作業スペース マップ検索

**Feature Branch**: `001-wifi-workspace-map`
**Created**: 2026-03-15
**Status**: Draft
**Input**: 現在地周辺の Wi-Fi 付き作業可能店舗を地図と一覧で探し、店舗詳細（Wi-Fi 有無・最安参考価格・住所）をボトムシートで確認できる

---

## Clarifications

### Session 2026-03-15

- Q: 検索方法は何をサポートするか → A: 現在地取得による検索のみ。テキスト・駅名検索は行わない。
- Q: 対象店舗の範囲はどこまでか → A: 主要チェーン系（スタバ・ドトール・タリーズ・マクドナルド等）に限定。個人店・小規模店は対象外。
- Q: 最安価格は店舗個別かチェーン共通か → A: チェーンブランド共通の参考価格。店舗ごとの個別価格取得は行わない。
- Q: 店舗詳細の表示形式は何か → A: 別画面ではなくボトムシートで表示する。
- Q: Wi-Fi 有無のデータはどう管理するか → A: 固定データ（アプリ同梱またはバックエンド手動登録）。リアルタイム取得は行わない。
- Q: フィルタ機能はどこまでサポートするか → A: MVP では高度なフィルタ機能は行わない。Wi-Fi 付き店舗のみ表示する固定フィルタのみ。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 地図で近くの作業スペースを探す (Priority: P1)

外出中にノート PC 作業ができる場所を探したいユーザーが、アプリを開くと現在地を中心とした地図が表示され、周辺の Wi-Fi 付きチェーン店がピンで示される。ピンをタップすると店名・チェーン共通の最安参考価格のサマリーが見える。

**Why this priority**: アプリの根幹となる体験。これ単体で「近くに作業できる場所がある」という最小価値を提供できる。

**Independent Test**: 位置情報を許可した状態でアプリを起動し、地図上に店舗ピンが表示され、ピンをタップするとサマリーが確認できれば成立。

**Acceptance Scenarios**:

1. **Given** アプリを初めて起動した状態で、**When** 位置情報の許可を与えると、**Then** 現在地を中心とした地図が表示され、半径 1km 以内の Wi-Fi 付きチェーン店がピンで表示される。
2. **Given** 地図に店舗ピンが表示されている状態で、**When** ピンをタップすると、**Then** 店名・最安商品名・チェーン共通最安参考価格を含む小さなサマリーカードが表示される。
3. **Given** 位置情報の許可を拒否した状態で、**When** アプリを起動すると、**Then** 位置情報が取得できない旨のメッセージが表示され、設定への誘導案内が出る。
4. **Given** 対象エリアに登録済みチェーン店が存在しない場合、**When** 地図が表示されると、**Then** 「周辺に対象店舗が見つかりません」と表示される。

---

### User Story 2 - 一覧で店舗を比較する (Priority: P2)

地図より一覧形式で比較したいユーザーが、リスト表示に切り替えると店舗が距離順に並び、各チェーンの最安参考価格を見比べられる。

**Why this priority**: 地図が直感的な発見を担うのに対し、一覧は比較・選択を助ける。地図（P1）があれば単体でも価値を出せる独立した補完機能。

**Independent Test**: リスト表示に切り替えた際に店舗が距離順に表示され、最安参考価格が各行に示されれば成立。

**Acceptance Scenarios**:

1. **Given** 地図画面が表示されている状態で、**When** 「リスト表示」ボタンをタップすると、**Then** 周辺の Wi-Fi 付き店舗が距離の近い順に一覧表示される。
2. **Given** 一覧が表示されている状態で、**When** 各行を確認すると、**Then** 店名・距離・最安商品名・チェーン共通最安参考価格が表示されている。
3. **Given** 一覧が表示されている状態で、**When** 「地図表示」ボタンをタップすると、**Then** 地図画面に戻る。

---

### User Story 3 - ボトムシートで作業可否と価格を確認する (Priority: P3)

候補を絞り込んだユーザーが、特定の店舗をタップするとボトムシートが開き、Wi-Fi の有無・最安商品名とチェーン共通参考価格・住所を確認して、行くかどうかを判断できる。

**Why this priority**: 地図・一覧の後に来る意思決定ステップ。P1・P2 が揃ってから自然に求められる機能。

**Independent Test**: 店舗を選択したときにボトムシートが開き、Wi-Fi 有無・最安商品・住所の 3 点が表示されれば成立。

**Acceptance Scenarios**:

1. **Given** 地図または一覧に店舗が表示されている状態で、**When** 特定の店舗をタップすると、**Then** 画面下部からボトムシートが開く。
2. **Given** ボトムシートが開いた状態で、**When** 内容を確認すると、**Then** 以下の情報が表示されている:
   - Wi-Fi 有無（あり / なし）
   - 最安商品名とチェーン共通最安参考価格（税込）
   - 住所
3. **Given** ボトムシートが表示されている状態で、**When** 下にスワイプまたは閉じるボタンを押すと、**Then** ボトムシートが閉じ、直前の地図または一覧に戻る。

---

### Edge Cases

- 位置情報の取得に失敗した場合（拒否・タイムアウト）、アプリはクラッシュせずエラーメッセージと設定アプリへの誘導を表示する。
- 周辺 1km 以内に対象チェーン店が 0 件の場合、空状態メッセージを表示する（地図・一覧とも）。
- 店舗データに最安商品情報が存在しない場合、「価格情報なし」と表示し、ボトムシート自体は表示できる。
- オフライン状態でアプリを起動した場合、ネットワーク接続を促すメッセージを表示する。
- 地図の表示範囲を大きく移動した場合の店舗再取得は MVP スコープ外とし、起動時の現在地固定データを使用する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: アプリはユーザーの現在地（緯度・経度）を取得できなければならない。位置情報取得のみをサポートし、テキスト・駅名検索は提供しない。
- **FR-002**: アプリは現在地から半径 1km 以内の Wi-Fi 付き主要チェーン系店舗を地図上にピンで表示しなければならない。
- **FR-003**: ユーザーは地図表示とリスト表示をボタン操作で切り替えられなければならない。
- **FR-004**: リスト表示では店舗を現在地からの距離が近い順に表示しなければならない。
- **FR-005**: ユーザーは地図のピンまたはリストの行をタップして店舗詳細をボトムシートで確認できなければならない。
- **FR-006**: ボトムシートには Wi-Fi 有無・最安商品名・チェーン共通最安参考価格（税込）・住所を表示しなければならない。
- **FR-007**: 位置情報が取得できない場合、ユーザーにわかりやすいエラーメッセージと設定アプリへの誘導を表示しなければならない。
- **FR-008**: 周辺に対象店舗が見つからない場合、空状態であることをユーザーに伝えなければならない。
- **FR-009**: 表示する店舗は Wi-Fi 付きチェーン系のみとする固定フィルタを適用し、ユーザーによるフィルタ変更は提供しない。

**スコープ外（MVP では実装しない）**:
- テキスト・駅名・住所での検索
- レビュー投稿・閲覧
- 予約・決済
- 個人店・小規模店舗への対応
- リアルタイム混雑・待ち時間表示
- 地図スクロール後の動的再検索
- 高度なフィルタ機能（価格帯・チェーン種別・距離範囲の絞り込み等）

### Key Entities

- **店舗（Venue）**: チェーン系カフェ・飲食店の 1 店舗。店名・住所・緯度経度・Wi-Fi 有無・チェーンブランド名を持つ。Wi-Fi 有無は固定データ（アプリ同梱または管理者手動登録）として管理する。
- **チェーン参考価格（ChainPrice）**: チェーンブランドに紐づく最安商品情報。店舗個別の価格ではなくブランド共通の最安商品名と参考価格（税込）を持つ。複数店舗で同一データを共有する。
- **現在地（UserLocation）**: ユーザーが取得した緯度・経度。検索の起点となる。アプリ起動時に 1 度だけ取得し、セッション中は固定で使用する。

### Assumptions

- 店舗データ（Wi-Fi 有無・住所・緯度経度）はアプリ同梱の静的データまたは管理者が手動登録した固定データソースから取得する。リアルタイム更新は MVP スコープ外。
- 価格データはチェーンブランド単位で管理する。スターバックスなら「ショートドリップコーヒー 330 円」のように、全店舗共通の参考価格として 1 件保持する。
- 対象チェーンブランドは主要チェーン（スターバックス・ドトール・タリーズ・コメダ珈琲・マクドナルド等）に限定し、初期データの網羅性は MVP では問わない。
- 検索半径はデフォルト 1km 固定とする（ユーザー変更不可）。
- 現在地は起動時に 1 度取得し、地図スクロールによる再検索は行わない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがアプリを起動してから周辺の店舗ピンが地図に表示されるまで、3 秒以内に完了する。
- **SC-002**: 地図表示からリスト表示への切り替えが 1 タップで完了し、0.5 秒以内に反映される。
- **SC-003**: 店舗をタップしてボトムシートが表示されるまで、0.5 秒以内に完了する。
- **SC-004**: 初めてアプリを使うユーザーが、位置情報許可から最初の店舗詳細確認まで 1 分以内に到達できる。
- **SC-005**: 位置情報が取得できない・店舗が見つからない・オフラインのいずれのエラー状態でも、アプリがクラッシュせず適切なメッセージが表示される。
